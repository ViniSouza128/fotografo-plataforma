Foco visível.
Teclado primeiro.

Acessibilidade aqui é contrato, não cortesia. Um --focus-ring único, ordem de tab previsível, atalhos catalogados, contraste AA garantido sobre obsidian, motion que respeita prefers-reduced-motion. Esta página fixa as regras e enumera os atalhos que já estão ligados em src/ hoje.

01 · Anel de foco

Um token. Vale em tudo.

Todo elemento focável herda --focus-ring de colors_and_type.css. Nunca remova outline sem trocar por este box-shadow, sob nenhuma hipótese.

01.A

Receita canônica

O anel é um halo duplo: 2 px do tom do fundo (preserva o contraste contra qualquer superfície) + 2 px Anchor Blue (a cor de interação primária). Aplique via box-shadow, nunca por outline — o anel precisa respeitar border-radius.

:focus-visible { outline: none; box-shadow: var(--focus-ring); }

01.B

Variantes por intenção

Em campos com erro, o segundo anel troca para --danger-500. Em ações destrutivas dentro de modal de confirmação, idem. Nunca abandone o primeiro anel --ink-100 — ele garante contraste sobre superfícies coloridas (chips ativos, badges).

:focus-visible { box-shadow: 0 0 0 2px var(--ink-100), 0 0 0 4px var(--danger-500); }

Demonstração — atoms focados simultaneamente

Esqueci a senha

Cada peça acima está permanentemente focada via classe .force-focus para QA. Em uso real, o anel só aparece sob :focus-visible — ou seja, no teclado, nunca no clique de mouse.

02 · Ordem de tab · skip link

O leitor entra direto no conteúdo.

Toda página deve ter um .skiplink oculto até o foco, que pula a navegação e leva direto a #main. Pegue isso de graça — três linhas de CSS, uma linha de markup.

02.A

Estrutura semântica obrigatória

Toda página real precisa, nesta ordem: <a class="skiplink"> · <header> com nav · <main id="main"> · <footer>. Não abra a página com um <div> genérico — o leitor de tela perde a estrutura.

Headings: h1 aparece uma vez por página (o título da página). Subseções usam h2, h3 em cascata sem pular nível.

02.B

Ordem de tab visível

A ordem natural do DOM é a ordem de tab. Nunca use tabindex="2" ou maior — gera labirinto. Use tabindex="0" só para tornar focável um elemento não-nativo (ex.: <div role="link"> no SponsorCard).

Em modais, a primeira coisa focada é o botão de fechar (canto sup. dir.) — não um campo do formulário. O esc sempre fecha.

Demonstração — skip link revelado por foco

Pular para o conteúdo principal ↑ .skiplink aparece quando recebe foco · navbar fica abaixo · #main é o destino

Receita: .skiplink { position: absolute; left: -9999px; } .skiplink:focus { position: absolute; top: 8px; left: 8px; padding: 8px 12px; background: var(--brand-500); color: var(--ink-1000); border-radius: var(--radius); box-shadow: var(--focus-ring); }

05 · Padrões ARIA

Leitor de tela acompanha o que muda.

Estado dinâmico (carrinho, loading, toast) precisa anunciar mudança. Use aria-live para regiões que atualizam, aria-busy para "carregando", role="link" para <div> clicável (e nunca o contrário).

05.A · aria-live

Mudança numérica do carrinho

O pill de contagem do carrinho na navbar é uma aria-live="polite": cada adição é anunciada como "2 fotos no carrinho · R$ 57,60" sem interromper o que o leitor está dizendo. Use aria-live="assertive" apenas para erros bloqueantes (PIX expirou).

<div aria-live="polite" aria-atomic="true">

05.B · aria-busy

Grade de fotos carregando

Enquanto o album carrega, o container da grade recebe aria-busy="true" e mostra skeleton. Quando os dados chegam, vira false e o leitor anuncia o conteúdo novo. Não remova o nó — anime o estado.

<section aria-busy="true" aria-label="Grade de fotos">

05.C · role="link"

SponsorCard como div-clicável

O SponsorCard é semanticamente um link, mas tecnicamente um <div> (porque carrega um lockup completo). Recebe role="link", tabIndex={0} e handler de Enter/Space. Já está em src/app/evento/[id]/page.js:1092 — siga o padrão para qualquer "cartão clicável".

<div role="link" tabIndex={0} onKeyDown={…}>

05.D · aria-modal + role="dialog"

Foco preso dentro do modal

Modais e drawers precisam de role="dialog" + aria-modal="true" + aria-labelledby apontando para o título. O foco entra na primeira ação destrutiva-segura (cancelar / fechar), Tab cicla dentro do modal, Esc fecha e devolve o foco ao gatilho.

Já está em Navbar.js:172 e useConfirmDialog.js:23. Gap: nem todo modal tem focus-trap formal hoje (ver contribution.html · deprecação).

05.E · alt-text de foto

Descreve sujeito + ação + local

Toda <img> em galeria deve ter alt-text de uma frase. Não use a numeração do arquivo. Exemplo: "Cavaleiro segurando a alça do touro durante o salto, arena central, Rodeio de Barretos 2026."

Para fotos sem descrição cadastrada, o sistema gera "Foto {n} · {evento} · {data}" como fallback — melhor que nada.

05.F · aria-label vs label

Quando usar cada um

Input com label visível: use <label for=…>. Botão-ícone (lixeira, fechar): use aria-label com a ação ("Excluir foto", "Fechar modal"). Nunca aria-label em um botão que já tem texto — duplicação confunde leitor.

Hoje há ~30 aria-label espalhados em src/. Auditoria de duplicação é dívida (ver deprecação).

06 · Motion sensível

Respeita prefers-reduced-motion.

O bloco já está em colors_and_type.css (linha 281): todas as durações caem para 1 ms. Você não precisa replicar — só nunca contornar com !important.

06.A

Token-driven

Use var(--duration-base), var(--ease-out) e parentes. O bloco @media (prefers-reduced-motion: reduce) reescreve todas as variáveis para 1 ms — uma fonte, uma vez. Suas animações herdam.

transition: transform var(--duration-base) var(--ease-out);

06.B

Animações longas → still

Para animações narrativas (loop do hero, badge pulsando, sheen em CTA), desligue o keyframe sob reduced-motion — não basta acelerar, o movimento incomoda. Use animation: none; dentro do bloco @media.

07 · Imagem & dados reduzidos

Lazy por padrão. Prioridade para o hero.

O cliente baixou as fotos com plano de 3G — toda imagem fora da dobra é loading="lazy". A capa do evento e a primeira fileira da galeria são loading="eager" + fetchpriority="high" para não atrasar o LCP.

07.A

Galeria · lazy-by-default

Fotos da grade pública usam loading="lazy" + decoding="async". A primeira fila (até 8 fotos) usa eager para que a tela pareça pronta antes da ponte WebSocket.

Tamanhos derivados (thumb / web / hero) já existem em storage/uploads/<eventId>/<kind>/<wm>/ — escolha o menor que cabe no slot.

07.B

Decoração nunca em <img>

Ícones de UI são SVG inline (sprite via <use href="#i-...">) — não <img>. SVG escala, herda cor por currentColor, não pede HTTP extra e não polui o cache de imagens reais.

Imagem decorativa (banner, padrão de fundo) que não carrega significado: alt="" e role="presentation".

08 · Checklist de PR

Cole no description de toda PR de UI.

Auto-revisão antes de pedir review. Se alguma linha falha, o PR volta antes de chegar ao reviewer.

  • Foco visível em todo elemento interativo — botão, link, input, chip, tab, row clicável.
  • Tab order segue o DOM. Sem tabindex > 0. Skiplink presente em página nova.
  • Esc fecha qualquer modal, drawer ou lightbox novo — testado com o teclado, sem mouse.
  • Sem cor sozinha sinalizando estado — toda badge tem rótulo textual além da cor.
  • Contraste de texto novo conferido em colors.html. Texto < 18 px só sobre pares AA+ da tabela.
  • alt-text em toda <img> de conteúdo; alt="" em decoração.
  • Botão-ícone tem aria-label com a ação real (ex.: Excluir foto, não Lixeira).
  • aria-live em região que muda sem refresh (carrinho, toast, contagem de upload).
  • aria-busy em container de skeleton — vira false só quando o conteúdo está utilizável.
  • Reduced-motion respeitado em qualquer @keyframes novo.
  • Atalho novo documentado em § 03 antes do merge — sem teclas secretas.
  • Mobile testado com VoiceOver/TalkBack (ou pelo menos rotor de leitura). Drawer recebe foco ao abrir.
