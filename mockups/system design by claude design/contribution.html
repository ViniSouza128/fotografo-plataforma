Como crescer
sem quebrar.

Esta página é o contrato entre o sistema e quem contribui. Diz como adicionar um componente novo, o que está proibido, como nomear, o que está marcado para morrer e quando quebrar a versão. Se algo aqui dificulta seu trabalho, essa é a discussão — não a violação.

01 · Adicionando um componente

Cinco passos. Sem atalho.

Um componente novo só existe quando atravessa todos os passos abaixo. Pular um quebra a costura — outro contribuinte vai recriar a mesma peça em três meses.

1

Verifique que já não existe

Procure em components-atomic.html (átomos: botão, chip, badge, ícone) e components-composite.html (compostos: cards, sumários, modais). Se for variante de algo existente — adicione como variante. Se for combinação de existentes — não é componente novo, é layout.

Atômicos Compostos Layout
2

Escreva no kit primeiro

O componente nasce em HTML estático dentro do kit apropriado antes de virar React/JSX. Isso força a usar apenas tokens, escolher um nome em pt-BR e descobrir os estados (rest · hover · focus · active · disabled · loading · empty · error) cedo. Não há atalho aqui — código React sem o cartão correspondente no kit é dívida.

Coloque também um preview card isolado em preview/components-<nome>.html — sumário visual de uma peça, sem ruído. Hoje o sistema tem 19 cartões em preview/.

3

Use só tokens

Toda cor, espaço, raio, sombra, duração resolve para var(--…) de colors_and_type.css. Sem hex novo, sem fonte nova, sem raio fora dos sete existentes, sem easing custom. Se o que você precisa não tem token — abra discussão (não invente um); se a discussão concluir que precisa de token novo, adicione ele primeiro ao CSS, depois consuma.

4

Documente estados & nome de classe

Toda peça precisa de pelo menos um cartão por estado: rest, hover, focus, disabled. Para conteúdo: pelo menos um empty, um loading, um error. Nome de classe segue a tabela § 03: .<peça> + .is-<estado> + .t-<intenção>.

Se a peça é exclusiva de uma superfície (raro), prefixe a classe: .admin-toolbar, .public-navbar. Compostos genéricos não têm prefixo.

5

Indexe no index.html & cite de onde nasceu

O componente novo só "existe" quando o card dele aparece no índice. Adicione link, número (04.X), uma frase de descrição e o estado (pronto, em revisão, planejado). Se a peça nasceu para resolver um caso real em src/, mencione o arquivo ("surge para substituir SponsorCard que hoje vive em src/app/evento/[id]/page.js:1080") — assim a próxima geração entende a razão.

02 · Regra "token-first"

O que está fechado para invenção.

A locked-list. Qualquer valor literal abaixo precisa vir do CSS, nunca do seu commit.

Proibido

  • Hex code novo. Inclui #fff, #000, #ddd, qualquer hex. Use a rampa de ink.
  • Fonte nova. Três famílias + Montserrat para LOGO. Acabou.
  • Raio fora da escala. 5px, 12px, 16px: não. Os sete raios são suficientes.
  • Easing custom via cubic-bezier ad-hoc. Três easings cobrem 100% dos casos.
  • Cor em rgba() que não vem do dim/glow tokens. Componha com --brand-dim e parentes.
  • Gradient além de --glow-radial (uma vez por viewport, atrás do hero).
  • !important sobrescrevendo token de motion (animation-duration, transition-duration).
  • Emoji como afordance de UI. Sempre line-svg via <use>.

Permitido

  • Novo token semântico que compõe tokens existentes (ex.: --success: var(--signal-500)). PR aceito.
  • Novo valor de espaço em casos justificados — abra discussão. A escala não cresce sem revisão.
  • Sub-marca nova só se o negócio adicionar uma vertical (Esportes, Natureza, Editorial cobriram tudo até agora).
  • Variante de chip/badge/tag reutilizando ramp existente. Inclua exemplo na página de átomos.
  • Keyframe novo desde que com fallback animation: none em prefers-reduced-motion.
  • Layout primitive novo em layout-primitives.html — uma grade ou um shell.

05 · Política de versão

SemVer aplicado ao visual.

O DS segue major.minor.patch. O major só sobe quando uma decisão de marca muda (paleta, fonte, voz). Minor introduz peças/tokens novos. Patch corrige texto, contraste, link.

v1.0.0

Major · marca decidida

Estado atual. Tokens fixos: paleta obsidian, Anchor Blue, Signal Green, três fontes + Montserrat (LOGO). Quatro verticais. Foundations · Brand · Atomic · Composite · Layout trancados.

Próximo major (v2.0) só se a marca mudar — não acontece sem decisão de Vinícius.

v1.x.0

Minor · peça nova

Sobe quando: nova vertical sub-marca, composto novo (entrando na página de compostos), layout primitive novo, aliases removidos (após período de tolerância).

Comunicação: changelog em index.html § 06 + entrada no log de deprecação se algo morreu.

v1.0.x

Patch · pequeno

Sobe quando: cópia ajustada, contraste corrigido, link quebrado, preview card novo sem mudança de token, typo. Não muda comportamento de nada em src/.

Sem comunicação formal — entra direto no commit, com referência no rodapé da página afetada.

Quebra prevista <-> superfícies em produção: antes de mergear breaking change (rename de token, remoção de classe), abra migration note em DESIGN-SYSTEM.md (repo root) listando: (1) o que muda, (2) grep para encontrar usos, (3) substituição mecânica, (4) janela de tolerância (alias por uma minor, remoção na próxima). Sem isso, contribuinte de boa-fé descobre que o DS quebrou o build dele.
06 · Em dúvida — defaults

Os padrões quietos.

Decisões pequenas que aparecem em quase todo PR. Memorize estas — economiza discussão.

Defaults canônicos

  • raiovar(--radius) · 8 px. Botão, input, dropdown, card padrão.
  • espaçovar(--space-4) · 16 px. Gap entre cards · padding interno padrão.
  • cor de textovar(--ink-900). Corpo. --ink-1000 só para ênfase.
  • duraçãovar(--duration-base) · 200 ms. Hover, troca de cor, fade.
  • easingvar(--ease-out). Padrão; só troque por motivo claro.
  • sombravar(--shadow-1) em sticky, --shadow-2 em hover, --shadow-3 em modal.
  • borda1 px solid var(--ink-500). Sempre 1 px. 2 px só em modal sob foco.
  • focobox-shadow: var(--focus-ring). Nunca outline só.
  • fonte de númerovar(--font-mono) em ID/hora; var(--font-display) em preço.
  • grade180 px público · 130 px admin. Galeria.
  • largura1280 px público + cliente · 1440 px admin · 720 px prosa.
  • modalCancelar à esquerda · primária à direita. Ordem canônica.
