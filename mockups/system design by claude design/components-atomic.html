01 · Botões

Six intentions, three sizes.

A hierarquia de ação na superfície é o trabalho mais sensível desses átomos. Cada botão declara o quanto ele "quer" ser clicado. Primary conduz a ação afirmativa principal. Success é reservado para dinheiro/confirmação. Secondary é a alternativa correta sem ser a recomendada. Ghost é descomprometido. Destructive é irreversível. Link-button é navegação inline com peso de botão.

Regra de hierarquia: nenhuma superfície tem dois botões btn-primary visíveis ao mesmo tempo. Se a tela exige duas ações fortes (ex.: Salvar e Cancelar), o secundário é btn-secondary; jamais dois primários. Em fluxos de checkout/pagamento, o primário é trocado por btn-success (verde signal) para sinalizar dinheiro.

03 · Seleção

Checkbox, radio, toggle.

Checkbox — múltipla escolha; radio — escolha exclusiva entre 2–4 opções visíveis; toggle — liga/desliga uma configuração com efeito imediato. Quatro ou mais opções de escolha exclusiva viram select.

Checkbox

Estados
Empilhada

Regra de empilhamento: checkboxes em coluna usam gap: var(--space-2) (8px). Em linha — uso raro — gap: var(--space-5) (20px). Texto-longo sempre quebra para a próxima linha, nunca alinha à direita do controle.

Radio

Estados
Grupo

Toggle

Estados

Quando usar toggle vs checkbox: toggle = efeito imediato e reversível (notificações, modo escuro, álbum público). Checkbox = parte de um formulário a ser submetido. Toggle nunca aparece em wizard/checkout.

check-row · variante de superfície (Patch v1.0.9)

Usado em formulários públicos (contato, remoção LGPD, cadastro) onde o checkbox precisa de mais peso visual — área clicável maior, borda de contenção e hover/focus explícitos. Estrutura canônica: <label class="check-row"><input type="checkbox"> <span class="check-row-label">Texto</span></label>

05 · Chips

Três famílias: status, filtro, eyebrow.

08 · Ícones

Sessenta e seis ícones em line-svg.

Sempre inline SVG, nunca emoji, nunca PNG, nunca Unicode glyph. Viewbox 24×24, stroke-width: 2, stroke-linecap: round, stroke-linejoin: round, fill: none. Cor herdada via currentColor — herda do texto pai. Tamanho via .ico.is-16/is-20/is-24/is-32 ou width/height inline.

11 · Tooltips

Top · bottom · left · right, sempre com seta.

Tooltips esclarecem affordances visuais — nunca contém ação. Texto curto (até 60 caracteres), uma linha. Aparecem após --duration-base (200ms) e somem em --duration-quick (120ms). Aqui mostramos as 4 posições com tooltip permanentemente visível.

Posições

Tooltip top Tooltip bottom Tooltip left Tooltip right

Acessibilidade: tooltip não é a única fonte de informação. Para ícone-só, sempre exporte aria-label na <button> — o tooltip é redundância visual, não acessibilidade.

12 · Loading

Spinner, skeleton, progress, upload.

Use spinner para esperas curtas (<3s) e ações sem progresso conhecido. Skeleton para esperas com forma previsível (cards, listas). Progress determinada quando você sabe o percentual; indeterminada quando é tempo desconhecido mas a tarefa progride. Upload-progress é o caso específico de transferência de arquivo.

∆ · Inconsistências

Mockup vs. live src/.

O DS canoniza o conjunto definitivo de atoms. O live src/ ainda usa tokens antigos (verde como acento, Inter/Space Grotesk, paddings ad-hoc, classes não definidas). Migrar é trabalho de produção — fora do escopo deste prompt. Esta tabela é o checklist para esse trabalho.

AtomMockup (canônico)Live src/Decisão
btn-primary · padding var(--space-3) var(--space-5) = 12 · 20 0.7rem 1rem = ~11.2 · 16 Mockup vence — alinha à grade 4 px. Mantenha o 0.7rem em live por enquanto (load-bearing em 47 lugares); migre quando tocar o arquivo.
btn-primary · cor --brand-500 Anchor Blue #1f7ae0 var(--accent) = #22c55e (verde signal) Mockup vence — verde é reservado para dinheiro (btn-success). Live src/ confunde acento com confirmação.
btn · convenção de classe .btn-primary (hyphen) — mantida .btn-primary (hyphen) Match. Não confundir com .btn primary (space) usado em mockups/frontend-final/ — esse é incorreto e será reconciliado.
btn-icon · btn-link Definidos aqui (36×36 / inline com sublinhado) Não definidos no CSS — 0 uses Mockup adiciona. Nenhuma migração pendente.
input · fundo --ink-400 = #232327 --bg-input = #222222 Mockup vence — alinha à rampa obsidian de 12 passos. Diferença é < 1%, migração indolor.
input · borda focus var(--focus-ring) (anel duplo) + borda --brand-500 border-color: var(--accent) sem anel Mockup vence — anel duplo é WCAG-friendly e é a regra única do sistema (token --focus-ring).
